## 5. 是否需要调整 — 判定标准

| 信号 | 阈值 | 建议动作 |
|------|------|----------|
| 近 7 天 L1 **≥ 85%** 且 Top 错误未恶化 | 稳定 | **维持 v4.2**，不扩 O1；优先 pos_capture relay + L3 混合方案 |
| 近 7 天 L1 **82–85%** | 可接受 | 导出错误 CSV，做 **targeted** 小步规则（broken 门禁） |
| 近 7 天 L1 **< 82%** | 告警 | 暂停扩规则；查 backend 是否加载 v4.2、错误是否集中某渠道/批次 |
| dry-run **L1 broken > 8** 或 **L2 broken > 3** | 门禁失败 | **不要上线/回滚**新规则，先收窄 |
| dry-run after − 线上 **> 3pp** | 规则未生效 | 查部署文件 mtime、`grep _ROADSIDE_BLOCK`、重启 backend |
| 「服务类→非问题」仍 > 40% L1 错误 | 主靶未解 | 下一批：**pos_capture / relay 豁免**，而非继续堆 O1 domain |

### 5.1 第一周实测判定（v4.2 已兑现）

- **已兑现提升**：近 7 天线上 L1 **87.04%**（对比部署前 79.95%，**+7.09pp**）；L2 **85.21%** 处于目标区间。
- **规则链状态健康**：dry-run L1 broken=3（≤8）、L2 broken=0（≤3），说明当前规则可持续。
- **是否需要调整**：**不建议大改/扩 O1**；建议进入「小步优化」阶段，优先处理 `服务类→非问题` 与 `产品质量类→非问题`。
- **距 MVP 90%**：近批次约差 **2.96pp**（约 38 条/1258 条），可通过 targeted 规则+复核闭环继续逼近。
