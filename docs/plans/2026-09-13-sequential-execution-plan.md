> 创建：2026-09-13

## 1. 执行纪律

每一步固定执行以下流程：

1. 只修改当前步骤授权的文件。
2. 在开发机完成测试、构建或数据校验。
3. 更新本文件的监督表和实际结果。
4. 创建一个原子 Git 提交。
5. 推送到 `feature/voc-l3-insight-rollout`。
6. 如涉及服务器，在开发机从该已推送 commit 生成离线包和版本清单。
7. 线下传递离线包；服务器核对 SHA256 后部署并回传验证结果。
8. 验收结论标为 `✅`；只有此时才开始下一步。

任何一项未满足，状态标为 `⚠️ 受阻`，不得通过并行开发绕过门禁。

### Git 门禁

- 每个步骤至少一个独立提交，不把下一步内容混入。
- 每次提交后立即 `git push`；推送失败即视为步骤未完成。
- 服务器不执行 `git pull/fetch/checkout`。
- 服务器只允许部署由已推送 commit 生成的离线包，不复制未提交的临时代码。
- 提交信息使用 `docs:` / `feat:` / `fix:` / `test:` / `chore:`。
- 禁止打包脚本自动把多个未审查改动混成一个提交。

### 生产红线

- 禁止全库运行 `apply_post_rules_to_v3 --write`。
- L3 改造不得修改 L1/L2 的评估口径和门禁阈值。
- 未通过 dry-run 不得切换生产默认路径。
- 32B 试跑不得占用生产分类时段。
- 每次服务器部署前备份 SQLite，保留回滚 commit 和数据库副本。
- 离线包统一命名：`VOC_<步骤>_<short-sha>_<时间>.zip`。
- 每个离线包必须附带 `VERSION_MANIFEST.txt`，记录分支、完整 commit SHA、生成时间、
  文件清单、包 SHA256、数据库变更说明和回滚包名称。
