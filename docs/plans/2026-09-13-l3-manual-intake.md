## 7. 汇报主题层与 214 个定位 L3 的映射（硬约束）

### 7.1 分层职责

| 层 | 建议规模 | 用途 |
|----|----------|------|
| L1/L2 | 现有口径 | 分类及准确率 KPI |
| **定位 L3** | **214 个** | 精确定位问题、检索工单、形成明细清单 |
| **汇报主题** | **约 30–45 个** | 管理层趋势、风险、行动方向 |
| 原始记录 | 逐条 | 数量佐证、代表原文和复核追踪 |

汇报主题不是另一套独立标签，而是 214 个定位 L3 的**稳定汇总层**。

### 7.2 映射规则

1. 每个定位 L3 必须且只能有一个 `primary_theme_id`，用于正式计数，避免重复统计。
2. 如某问题确实涉及多个主题，可配置 `secondary_theme_ids`，但只用于关联检索，**不参与数量汇总**。
3. 映射使用稳定 ID，不依赖可修改的中文名称。
4. 映射表必须版本化；每份汇报记录 `taxonomy_version` 和 `theme_mapping_version`。
5. `其他-待归类` 单独映射到 `T99`，显示数量和清单，但不混入任何正式主题。

建议文件：`label_project/l3_report_theme_mapping_v1.json`

```json
{
  "_meta": {
    "version": "v1",
    "scope": ["产品质量类", "服务类"]
  },
  "themes": {
    "T-Q-01": {
      "name": "充电设施与充电可用性",
      "l1": "产品质量类",
      "owner": "充电业务",
      "definition": "覆盖车端、家充、闪充及第三方充电设施故障"
    }
  },
  "l3_mapping": {
    "产品质量类/LFC问题/闪充站问题": {
      "primary_theme_id": "T-Q-01",
      "secondary_theme_ids": []
    }
  }
}
```

映射键使用 `L1/L2/L3` 完整路径，而不是只用 L3 名称，防止未来出现同名标签。

### 7.3 数量口径与佐证链

每个汇报主题都必须同时提供三层数据：

```text
汇报主题：充电设施与充电可用性（本期 186 条）
  ├─ 闪充站问题：82 条
  ├─ 家充桩问题：51 条
  ├─ 无法充电：37 条
  └─ 其他定位 L3：16 条
       ↓
  明细清单：opinion_id / 日期 / 车型 / 区域 / L1/L2/L3 /
            复核状态 / 脱敏 VIN / 原文摘要
```

正式计数公式：

```text
主题数量 = 该主题 primary_theme_id 下去重 opinion_id 的数量
```

不得用二级关联主题重复计数；同一条记录在同一主题内只计一次。

### 7.4 汇报必须输出的佐证

| 输出 | 要求 |
|------|------|
| 主题总量及环比 | 显示本期、上期、变化量和变化率 |
| L3 构成清单 | 列出该主题下所有有数据的 L3 及数量 |
| 工单明细 | 支持导出 CSV；至少包含 `opinion_id`、日期、车型、区域、L3、复核状态、原文摘要 |
| 代表原文 | 默认展示 3–5 条，必须来自明细清单 |
| 口径信息 | 显示时间范围、是否仅已复核、映射版本、样本覆盖率 |
| 复核分层 | 已复核与模型未复核数量分开显示，不能混成同一可信口径 |

建议 API/文件结构：

- 主题汇总：`GET /api/report/themes`
- 主题下 L3 构成：`GET /api/report/themes/{theme_id}/l3`
- 主题明细：`GET /api/report/themes/{theme_id}/records`
- 导出：`GET /api/report/themes/{theme_id}/export.csv`

### 7.5 映射质量门禁

- 214 个定位 L3 的主映射覆盖率必须为 **100%**
- 一个定位 L3 不得有两个主主题
- 主题汇总数必须等于其 L3 明细去重后数量
- 抽查任意主题，汇报数量、L3 小计、导出清单三者必须一致
- 映射变更后旧汇报仍按原版本可复现
- 前 10 个高频主题逐条人工复核边界定义，避免主题重叠

### 7.6 实施顺序

1. L3-1 定版 214 个定位标签。
2. 产出约 30–45 个汇报主题及边界说明。
3. 完成 214 → 主题的 100% 主映射，并生成反向清单。
4. 运行一致性检查脚本：漏映射、重复主映射、无效路径、汇总对账。
5. 接入 `analytics_engine.py` / `report_aggregator.py`。
6. 在 `DataReport.vue` 增加“主题 → L3 → 原始记录”三级下钻和 CSV 导出。

在第 3、4 步完成前，汇报主题层不得用于正式对外汇报。
