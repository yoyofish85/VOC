## 2. 你反馈的现象：可能原因（按优先级）

**现象**：停测 1–2 周后，第二批首次分类「几乎全是服务类」；再次运行后感觉准确率下降。

| 优先级 | 原因 | 代码/系统依据 | 如何验证 |
|--------|------|---------------|----------|
| **P0** | **Ollama 未就绪/模型未加载**，走了异常或兜底路径 | `classify_text` 失败时 l1 为空；LabelMatcher 兜底默认 **服务类**（`offline_validate.py`） | 看 `v3_match_type` 是否含 `llm_fallback` / `qwen_parse_failed` |
| **P0** | **首次坏结果被推理缓存复用** | 缓存文件 `src/backend/qwen_inference_cache.json`；二次运行 `cache_hit=true` | 查 meta 里 `cache_hit` 比例 |
| **P1** | **停服后冷启动**，首批在 Ollama 未稳定时开跑 | 首条推理可能慢/异常；无预热 | 看 route_metrics 的 `llm_failed`、首批 duration |
| **P1** | **误用 MLX 或错误启动脚本** | `start_mlx.sh` 设 `VOC_USE_MLX=1`；LoRA 已暂停 | 启动时必须 `./start_ollama.sh` |
| **P2** | **同一批重复分类**覆盖 v3，与首次坏结果混合 | 批内部分成功/部分失败 | 对比两次 route_metrics 与批内 L1 分布 |
| **P2** | **规则后处理过度拉回服务类** | `non_issue_guard` / `service_quality_guard` | dry-run 对比 before/after |

**重要**：14B 直推路径（默认 `VOC_QWEN_DIRECT=1`）解析失败时 **不会** 默认写「服务类」，而是空标签 + `qwen_parse_failed`。  
若批内 **100% 服务类** 且 match_type 为 `qwen14b_structured`，更可能是 **模型真输出** 或 **缓存命中首次坏结果**。

### 3.3 问题批次分布诊断（核心）

```bash
python3 <<'PY'
import sqlite3, json
from collections import Counter

DB = "src/backend/opinion_review.db"
BATCH = "<BATCH>"  # ← 改成实际批次名

conn = sqlite3.connect(DB)
rows = conn.execute("""
  SELECT opinion_id, v3_l1, v3_l2, v3_match_type, v3_confidence, v3_label_meta, review_status
  FROM opinion WHERE upload_batch = ?
""", (BATCH,)).fetchall()
print(f"批次 {BATCH} 总行数: {len(rows)}")
print("L1 分布:", Counter(r[1] or "（空）" for r in rows).most_common(8))
print("match_type:", Counter(r[3] or "（空）" for r in rows).most_common(8))
cache_hit = err = Counter()
for r in rows:
    try:
        m = json.loads(r[5] or "{}")
        if m.get("cache_hit"): cache_hit["cache_hit"] += 1
        if m.get("error"): err[str(m["error"])[:80]] += 1
    except Exception:
        pass
print(f"cache_hit 行数: {cache_hit.get('cache_hit', 0)}")
print("error Top:", err.most_common(5))
print("review_status:", Counter(r[6] for r in rows))
PY
```

**读结果**：

| 若看到 | 含义 | 下一步 |
|--------|------|--------|
| L1 几乎全「服务类」+ `qwen14b_structured` | 模型真输出或缓存 | 做 3.4 预热 + 考虑清缓存 |
| 大量 `qwen_parse_failed` / l1 空 | Ollama/JSON 解析失败 | 重启 `ollama serve`，勿整批重跑 |
| 大量 `llm_fallback` | 走了 LabelMatcher 兜底 | 查 Ollama 模型是否在列 |
| `cache_hit` 占比高 | 二次运行命中坏缓存 | 执行 3.5 清缓存后再测 |

### 3.4 三条冒烟（分类前必做）

```bash

```
