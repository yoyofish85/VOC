## 2. 总体结论

Cursor 方案做对了三件关键的事：

1. **用「阶段 0 实测」推翻原假设、重写任务**——把"融合人工 L3 与提取关键词"重写为"收敛 + 主题分层"，把"重建生产映射"重写为"不重建、只消化通用"。
2. **把「透视 vs 提取」的分界讲清**——跨记录关联才是透视，单条结构化只是透视的输入。
3. **全程门禁化、可回滚、可复现**——`evidence_sql`、版本化映射、SHA256 离线包、严格串行监督表。

结论：**可直接作为执行基线**。以下是需补强的点与新增优化建议。

## 3. 分块评估

### 3.1 硬件与模型升级（§2 + S10/S11）

**合理**：按角色拆模型（32B 分类 / 72B 汇报 / bge-m3 嵌入 / 14B 回滚）、128GB 内存预算（常驻约 64GB，留约 26GB）、先硬件后模型 + 一周同机基线、dry-run 硬门禁。

**需补强（重点 3 条）**：

1. **holdout 有选择偏差**：`baseline L1=90.07%（272/302）` 明显高于全库 `85.01%`。holdout 从复核样本随机抽、偏向易判样本，**仅凭 holdout A/B 会偏乐观**。门禁必须叠加「全库近 7 天 dry-run + 新批次连续 2 批 ≥200」，并明示「holdout 不代表全库」。
2. **候选模型可放宽**：分类主力除 `Qwen3-32B`，同测 `Qwen3-30B-A3B`（MoE，活跃 3B，更快更省内存）；汇报除 `Qwen3-72B`，二期评估 `Qwen3-235B-A22B`（总量偏紧，需实测）。
3. **汇报质量缺可量化验收**：换 72B 写汇报若无 rubric，验收会沦为"感觉更好"。建议先定**人工盲评 rubric**（结论准确性 / 可读性 / 数字与依据一致 / 无编造）作为 M-3 的 A/B 验收标准。

### 3.2 L3 三级标签（§3 + S3/S4/S5）

**合理**：结论「聚类 492 中 488 已在人工体系内 → 不需要融合」正是对"融合"诉求的正解；214 定位 + 30–45 主题 + 305 别名；L3 暂不进 KPI；主攻「通用」22.5%（根因已定位为 `generic_l3` + 4 个 L2）。

**需补强**：

1. **「提取的三级关键词」应定位为「新词发现候选池」**：`l3_phrases / extracted_keywords` 周期性反哺别名层（月度评审新 L3），形成闭环，而非一次性融合。
2. **人工 L3 采集应由「建议 C」升级为「本期必做」**：`review_l3` 全空 → L3 永远无金标、无法自动评估。选 C（仅高频 L2、默认采纳模型值、只错改）成本极低，是方向一可持续的前提。
3. **L3 评估需配套「判读口径样本库」**：无金标时 `eval_l3_accuracy.py` 的 Top-1 70–80% 目标无从验证，建议每月人工判读 200 条建半自动基准。
4. **别名「同 L2 内就近」有漏洞**：充电域同一根因横跨 `LFC问题 / 车端充电问题` 等多个 L2。别名层应允许**跨 L2 映射到定位 L3**，或明确交由 R-6 语义聚集兜底，避免重复 L2 切碎问题。

### 3.3 汇报洞察（§4 + S6/S7）——方案精华，方向正确

**合理**：确定性字段 → 跨记录透视 → LLM 只表达不发现；洞察模板库 I1–I10 + `evidence_sql`；severity 加权；生命周期五态；VIN 复发（填充 67.9%、复发主体 55.6%）数据条件成立。

**需补强（重点 3 条）**：

1. **车型/区域集中度（I3）必须有外部基准分母**：`lift = 某 L3 在车型 A 占比 / A 车型保有量占比`。无「各车型保有量/销量」时，lift 会被销量结构误导 → 无数据则 I3 先降级为区域版（country 98.1% 填充可用）。
2. **洞察模板加最小样本量与显著性门槛**：n≥5、lift≥2 且卡方 p<0.05、环比 delta 超置信区间，避免小样本噪声上管理层汇报。
3. **72B 写结论必须事实锚定 + 后置校验**：prompt 强制「只基于传入数字、无数据不写」，并对输出做「数字与传入一致」的机械校验，杜绝编造。

### 3.4 执行与工程（S0–S11）

**合理**：严格串行 + 原子 Git 提交 + 离线包 SHA256 + VERSION_MANIFEST + 监督表 + 红线，符合「服务器离线无法 Git」约束。

**需补强**：

1. **纯只读/文档类步骤可并行压缩 8 周**：S1（工具链）、S3（L3 定版，纯 JSON+文档）、S4（主题映射）不碰生产链路，可与 S2 并行。
2. **补「数据治理」小项**：`reviewer` 历史全空、部分已复核未归档、35 条缺 review_l1，会干扰主题对账与准确率分母。
3. **Ollama 版本兼容**：Qwen3-32B/72B 需较新 Ollama，S10 前先确认服务器版本。

## 4. Cursor 方案之外补充的优化方向（4 条）

1. **「汇报 → 治理」反哺闭环**：洞察命中样本自动回喂（如 I1 复发高 → 提示某 L3 别名/关键词缺失 → 补别名），让洞察不止"看"还能"改"。
2. **真实闭环状态替换代理口径**：现在 `reflow_synced` 是「已处理」代理；接入售后技术提案/QMS 后，用真实工单闭环状态让 `unmet_rate`、首次解决率更硬。
3. **意图与标签交叉一致性校验**：`intent=投诉升级` 不应落在「表扬」，`severity=高` 不应落在「咨询」。
4. **洞察模板库开放为可配置 JSON**：运营/业务可自行加「分析假设」，不必每次改代码。
